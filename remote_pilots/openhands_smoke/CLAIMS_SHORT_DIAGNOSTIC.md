# v3 短证据能力定位

目的：在不改 v3 提示、schema、温度、分块和输出预算的条件下，查看误读是否仍发生于单个完整动作—观察对。七次调用，不训练、不修改分段器、不重启 Qwen 服务。

## 远程命令

保持原 qwen-local 服务运行，从仓库根目录执行：

```bash
cd ~/online-failure-attribution
git pull --ff-only
python -m remote_pilots.openhands_smoke.claims_short_diagnostic run
```

回传整个 `out/swe_claims_short_v1/`。脚本自动保存模型元数据、输入、原始输出和失败信息。无需复制长日志。标准库即可运行，无新增 GPU 依赖。失败仍保留结果并返回非零状态，不自动重试。

Linux 上尝试识别当前用户可读的已知 Qwen 服务进程，采集允许列表中的 model-path/model-name/port/context-limit、服务文件指纹、服务解释器的 torch/transformers 版本、模型配置的选定字段、tokenizer 文件指纹及权重文件名/大小。不会保存完整命令行、环境变量、密钥，也不读大权重内容。

若自动识别不到，结果仍可运行；下一次可增加 `--model-path /实际模型目录`。该参数只用于读取配置，不加载或更换模型。元数据明确记录局限：候选进程不保证拥有请求端口，磁盘配置不证明实际内存权重、量化或 dtype。启动的服务文件也可能与磁盘版本不同，不宣称完整身份验证。

## 七个诊断窗口

| 来源与步骤 | 检查内容 |
|---|---|
| Keras 12 | 编辑不是验证成功；要求复核不是已复核 |
| Prettier 27 | 编辑回执末尾的命令式提示 |
| Keras 17 | absl present? False 的否定理解 |
| Keras 18 | import 失败与脚本内成功打印语句的区分 |
| Prettier 28 | 失败示例的错误与退出码 |
| Prettier 31 | 成功示例的有限范围，不能推断全测试通过 |
| Prettier 35 | 提交成功与消息意图、功能验证的区分 |

所有窗口保留完整 action/observation 原文及引用映射，无人工删除错误、提示语或噪声。期望答案单独保存，不进入模型请求。步骤35与先前单步阶段具有相同证据，是重复对照；不是独立新样本。

这是根据已观察错误挑选的开发诊断，单步窗口不是 gold stage。变短同时改变上下文和信息选择难度，所以改善只能说明短证据更容易处理，不能直接证明长上下文是唯一原因；仍出错也不能排除 prompt/template 或服务设置因素。七次是一次性诊断，不估计随机输出的稳定误差率。

回传后分别核验格式、否定/时态、实际引用支持和关键内容覆盖；尤其检查源码/回执中的文字是否被当成执行事实。若短证据仍误读，先结合模型配置决定是否做小批更强模型对照。若改善，则优先研究输入组织与选择，不直接改成每步 LLM 或单步 stage。没有语义通过结论前不连接在线报警。
