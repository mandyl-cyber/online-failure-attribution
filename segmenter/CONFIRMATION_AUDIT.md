# 即时/延迟确认对照与错误审计

2026-11-12。执行范围：原有 461 条轨迹、18,636 步、固定任务/内容组五折；无需新增人工标注，不调用生成式 API。ModernBERT 受控微调另行在后台执行。

## 结论与当前决策

本轮不将在线默认模型改成统一延迟确认，也不提升编码器为默认后端。晚一步带来的最终 F1 提升较小，来源间不一致；考虑真实提交时间后没有胜过即时模型。错误审计发现了明确的输入缺陷：原转换器遗漏公开任务列表的内容。已恢复为独立旁路文件并做一次固定的轻量探测，但尚未修复默认适配器或发布新在线模型。

恢复计划状态后的即时模型最终 F1=0.5653、D0=0.5083，相比同配置控制 0.5576/0.5044 有小幅改善，仍远低于 0.70。当前最值得推进的是保留即时结构事件检测、完成受控微调，并基于版本化的完整工具输入验证计划状态的价值；不能把本轮结果解读成语义方法已被否定。

## 1. 延迟实验是真实使用后续观测

`confirmation.py` 保存有限长度缓冲：候选边界 b 在 b+d 的动作和观察到达后才产生特征与预测，d=0/1/2。特征包含候选处既有四步历史，以及之后 d 步的当前结构特征。模型固定为 C=1 的 LR；每折仅使用训练任务拟合，下一折作为开发集选阈值，外层任务只评价。

阈值优化的是该方案时限下的开发集 ±1 边界 F1。所有预测同时报告精确匹配、最终 ±1 及 D0/D1/D2，不能只改变评分截止时间就宣称模型提升。`wait_only` 对照保持即时模型的预测内容，只推迟提交、不看新证据。

末尾没有足够后续步骤的候选不确认，不虚构 EOS 观察，也不补写即时提交时间。d=1/2 分别留下 61/128 个无法确认的金标边界，仍保留在召回分母中。步骤延迟不等于固定毫秒延迟；真实 agent 一个动作的耗时可能很长，本实验未验证干预窗口安全性。

| 方法 | 精确 F1 | 最终 ±1 F1 | D0 F1 | D1 F1 | D2 F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定即时 LR | 0.4368 | 0.5576 | 0.5044 | 0.5576 | 0.5576 |
| 看后续一步并确认 | 0.4419 | 0.5703 | 0.1333 | 0.5128 | 0.5703 |
| 看后续两步并确认 | 0.4326 | 0.5608 | 0.0000 | 0.1458 | 0.5060 |
| 只等一步、不用新证据 | 0.4396 | 0.5658 | 0.1495 | 0.5117 | 0.5658 |
| 只等两步、不用新证据 | 0.4354 | 0.5592 | 0.0000 | 0.1487 | 0.5061 |
| 之前已选出的 LR | 0.4384 | 0.5599 | 0.5057 | 0.5599 | 0.5599 |

之前的 LR 做过开发配置选择，所以不是本轮固定 C=1 的严格同配置控制。“只等”对照的最终分数也变化，是因为末尾预测不再提交；不能将这部分变化归因于新增证据。

任务组 bootstrap 1000 次、95% 区间（单位：百分点）：

- 看一步相对固定即时模型的最终 F1 增益：[+0.3619,+2.2005]，但与只等一步比较，在共同 D1 时限下为 [-0.7691,+1.0179]，没有稳定的新证据收益。
- 在共同 D1 时限下，看一步相对即时模型为 [-5.6563,-3.2991]，说明全面等待会损害及时性。
- 看两步相对即时模型的最终增益为 [-0.7383,+1.3258]；共同 D2 时限下相对只等两步为 [-1.0349,+0.9900]。

来源拆分（最终 ±1）：SWE 即时/看一步/看两步为 0.5919/0.6196/0.6145；Terminal-Bench 为 0.5157/0.5094/0.4962。因此，不能把总体微小上升当作两类场景都有效。

## 2. 错误审计：能观察到什么，不能证明什么

以之前 LR 的 `tol1_D0` 一对一匹配为基准，导出全部漏检与误报。漏检有 987 个，其中按互斥优先级划分：

| 可观测类别 | 数量 | 含义 |
| --- | ---: | --- |
| 附近存在晚到预测 | 180 | 边界附近有预测，但不满足 D0；不等同于模型完全没发现转折 |
| 其余漏检处工具类别发生切换 | 626 | 有结构变化，但它本身不足以唯一决定工作阶段 |
| 其余漏检处工具类别未切换 | 181 | 阶段可能在同类操作内部变化，粗工具类别不足以描述 |

2,096 个误报中，2,077 个（约 99.1%）位于工具类别切换处。常见转移包括 PLAN→READ、EXEC→EDIT、VERIFY→EDIT。这个统计说明错误与工具切换高度重合，不能单凭相关性证明模型内部的因果机制。

已按来源、错误类型、不同轨迹抽取案例并核读。例子包括：

- SWE Ansible `5b83347a`：标注边界在第 8 步读取代码，编辑发生于第 9 步；第 23 步计划更新接第 24 步验证。需要区分“开始准备下一阶段”与“第一条明显动作”，不能直接把相差一步当成标注错误。
- SWE `e6e185ca`：运行 pytest 失败后读取依赖文件。换工具仍可能服务于同一个验证/环境排查过程。
- Terminal-Bench `7498555b`：连续编辑中一次编辑失败，随后读取定位；同类编辑内部也可能有阶段边界。另有环境检查中插入 think 工具导致工具类别改变，未必是新的工作阶段。
- Terminal-Bench `9f75877e`：Python 下载与 curl 下载之间换工具，但两者仍在准备数据。

这些是诊断案例，不是新增金标。仅凭一套阶段标签，无法可靠计算“当时证据充分”“必须看未来”“标注有歧义”三类真实比例。本轮保存代理类别和上下文，不把自动分类写成因果结论。也没有使用隐藏 thought。

事件检测已经逐步执行：`run_online.py` 先检测事件、更新状态树和引用，再更新 stage；触发条件直接取事件和依赖。它没有等待阶段封口后才检测事件。当前同线程若后端阻塞仍可能拖慢返回，本轮未实现异步隔离或声称真实部署完成。

## 3. 发现并恢复了计划输入缺陷

`adapters/openhands.py` 的 `_s()` 将列表中的所有字典当作文本内容片段，只读取 `text` 字段。实际 `task_tracker.task_list` 的字典使用 `id/title/status`，结果多项任务列表变成空行。

完整审计结果：1,649 个 task_tracking 步骤中有 1,378 个动作为空，涉及 270 条轨迹。已按 `records.json` 中的原始工具调用 ID，从对应原日志恢复全部 1,378 个空动作；未恢复数为零。调用 ID 冲突会报错；恢复字段只保留公开 command 与任务 id/title/status，不读 thought 或人工标签。

**此前“指纹一致”的准确含义是：重新转换的 action/observation 与旧转换结果一致。它不能证明转换器保留了原日志的所有字段。** 这次审计定位的是已有转换口径的信息损失，而非原始数据没有计划信息。

恢复结果保存在 `eval/plan_payload_audit/payloads.jsonl`，原日志路径与 SHA256 记录在同目录 `report.json`。既有训练输入、默认转换器和在线模型没有被静默替换。

额外做了一次预设 C=1、四步历史、即时 LR 的轻量输入探测：仅加入公开计划状态变化、完成项数量、活动任务变化、更新间隔；不把标题、任务 ID 或 thought 当作模型输入。任务 ID 仅在单条轨迹内对齐更新，新模型文件用包装元数据阻止直接当作旧在线模型加载。

| 方法 | 最终 ±1 F1 | D0 F1 |
| --- | ---: | ---: |
| 同配置原结构控制 | 0.5576 | 0.5044 |
| 加恢复的计划状态特征 | 0.5653 | 0.5083 |

最终增益区间为 [+0.0634,+1.4910] 点，D0 为 [-0.2918,+1.1786] 点。修复探测的 SWE 为 0.6110/0.5514，Terminal-Bench 为 0.5096/0.4559。提升有限且来源不一致，尚不部署。它是由本轮错误审计启发的探索实验，不能宣称独立确认；没有反复搜索参数，也未接触旧 119 条外部任务。
