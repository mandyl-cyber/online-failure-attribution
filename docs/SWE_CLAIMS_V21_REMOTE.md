# Claim v2.1：仅修订抽取规范

## 变化与冻结项

根据六条开发请求的 AI 复核，仅更换 system instruction：
每个事实必须由实际引用片段支持；比较引用两侧；命令输出必要时引用动作；保留条件、否定和声明/执行的区别。
优先代码约束、修改差异、验证结果和未解决事项；合并重复和计划，避免文件大小等无关清单。
objects 使用原文路径、符号、工具或测试名称。不增加字段、分类器、关系图或报警模块。

schema、原始文本、证据编号、分段、最多六条 claim、2048 输出 token、temperature=0 均不变。
提示词变长，其输入 token 与耗时必须单独报告。旧 v2 运行器和提示词文件不修改。

## 18 次调用

1. development_revised：旧六条输入，新规范；旧响应已回传，作为开发对照，不重复调用。
2. holdout_baseline：额外任务的六条输入，旧规范。
3. holdout_revised：相同额外六条输入，新规范。

额外样本取现有 48 请求中不属于前两个任务的任务，按 ID 排序选第一项，每种分段取最早和最晚可用阶段。
选择只使用任务/阶段元数据，没有按模型表现筛选。任务与提示词开发集隔离，但该任务在项目旧实验中出现过，不能宣称全项目独立测试集。
三种分段的阶段可能重叠且长度不同，不据此排名划分器。仅一个额外任务，不证明泛化准确率。
输入和提示词指纹已写入 `pilot/swe_claims_v21/protocol.json`；修改后须建立新版本。

## 远程运行

使用原有 Qwen 服务和 Python 环境，无新增依赖：

```bash
cd ~/online-failure-attribution
git pull --ff-only
python -m remote_pilots.openhands_smoke.claims_v21 run
```

传回整个 `out/swe_claims_v21/`。其中每组包含 config、原始响应、summary 和待审核 semantic_review。
输出目录与旧结果分离。每作业一次尝试，已有结果（包括失败/reserved）不自动重试；同命令续跑不会重复已调用作业。
网络预检失败可在服务恢复后重跑同命令。不要修改已有输出文件来强制重试。
脚本不会自动扩大到全部48条，也不会把格式合法自动算作语义通过。

## 复核与门槛

先校验指纹和证据映射，再按原 v2 标准审查全部输出：引用支持、条件保留、源码/运行区别、重复、对象和重要遗漏。
保留失败和空输出；支持率必须同时报告数量和遗漏，防止少输出换取看似较高的支持率。
新样本先不根据结果继续改规范；报告按开发/额外任务分开，AI 复核不是人工金标。
如额外样本仍出现明显不相关引用或条件反转，暂缓全量运行。完整运行阶段也不等同在线报警效果。

本地检查：`python -m unittest discover -s tests -p "test_claims_v*.py"`。
本轮只完成准备与模拟测试，尚无 v2.1 远程效果结论。
