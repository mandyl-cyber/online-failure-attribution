| --- | --- | --- | --- |
| 1 | 版本化输入修复与证据存储 | openhands adapter、audit_plan_payloads | 计划字段恢复；原生步号不变；可按摘要回查原文 |

## 必需行为验证

1. 前缀不变性：更换未来步骤，不改变过去已产生的记录。
2. 人工阶段拆分/合并只改变 Membership，不丢原始证据或改 entry ID。
3. 测试在错误目录或不同包版本运行时，最多支持该次命令结果，不能支持当前补丁正确。
4. 后续回退和反驳可被检索，旧证据仍保留；API 必须能区分已修复错误与仍有影响的候选。
5. 模型引用不存在、跨轨迹或越过 cutoff 的证据时，输出验证失败，不能悄悄替换引用。
6. 阶段整理超时/失败不会阻塞每步落盘；重试不生成重复条目，成本不重置。

## 对照解释与决策

- A 原始轨迹：完整原文超出预算时保留该样本为 context_overflow，另报所有方案均可容纳的配对子集；不静默截断或丢样本。
- B 人工阶段＋账本＋关系＋原文回查：验证所选账本设计能否保留信息，不宣称在线结果。
- C 与 B 共用同一份 entries，但隐藏所有显式关系及携带关系的辅助摘要；测得的是显式边的增益，文本仍可能隐含关系。
- D 在线阶段＋同一账本生成策略＋关系＋回查：后续接入。比较 B/D 时冻结 API 模型、提示及输入版本。
- 如果 B 落后 A，先查证据保留；如果 D 明显落后 B，再优先改划分；如果 B/C 无稳定差异，先简化边，不能默认训练更大模型。

所有成本从输入准备后的语义整理开始累计，包含阶段整理、图推断、检索后的模型调用、最终归因和重试。额外报告仅最终归因成本，但不能拿它冒充端到端成本。本地 CPU/GPU 时间与 API 等待分别记录。

没有 claim/edge 金标时，只报告出处有效率、对象/版本约束检查和下游消融，不能报告语义准确率。40 条开发实验不用于发布显著性结论；正式实验按任务组配对 bootstrap 并分来源报告。

## 运行边界

当前 API 配置为空、网络执行禁用、运行模式 dry_run。准备程序完成不表示账本或 API 已完成。下一步应实现第 1—3 项的本地最小原型；不启动新的模型训练，不新增人工标注任务。模型、服务商、数据外发范围及费用上限落实后才启用真实调用。
