# 在线阶段封口与 claim 入账

2026-11-13。实现入口：`segmenter/online_ledger.py`。本版本贯通原生 OpenHands 实时事件 → phase 规则划分 → 阶段封口 → 持久化作业 → 后台多 claim 入账。没有使用人工阶段、最终步数或离线消息折叠；没有调用 API。

## 使用

```powershell
python -m segmenter.online_ledger <session>/events.jsonl --out out/live_claims --run-id session-001
# 也支持原生 events/ 目录。
# 用相同输入、out 和 run-id 重启；历史事件按原生 ID 去重。
```

输入是 OpenHands 原生事件，不是已有 `steps.jsonl`。事件必须有稳定 ID；观察应晚于对应动作到达。当前输入源要求追加且不改写，不支持日志轮转、截断或多个写入进程。没有文件偏移检查点；重启从头扫描输入并按持久化 ID 去重，恢复成本随历史增长。

- 每个动作与观察配对后写证据，未完成的动作保持 pending，不强制形成完整步骤。
- 实时划分目前固定 phase 规则模式，未接监督模型；不改变原有 `run_online` 默认行为。仍需评估在线归因损失，不能把本次贯通解释为边界准确率提高。
- 当前阶段中的确定性描述保存在 `buffered_candidates`，正式 entries 为空。阶段封口时将该阶段证据及候选冻结成作业；后台抽取器生成零到多条 claim，一次原子提交。
- 阶段边界位置和 `detected_at_seq` 分开，后者是确认时已完成步骤数；拉回中性步骤时也不把未来阶段证据带入旧阶段。
- 新阶段接收不会等待 claim 抽取；规则抽取器目前支持公开计划、状态变化候选、验证观察和完成自述。`generate_claim_batch(job)` 是后续语义抽取器的替换接口，尚无 API 客户端。
- stage 是触发和组织单位，claim 才是正式节点；不同步骤的重复语义尚未做合并，跨阶段同一 claim 的语义修订也尚未实现。

## 输出与可见性

| 路径 | 内容 |
| --- | --- |
| `native_events/` | 按到达顺序原子保存的事件，用于恢复配对器与划分器；审计内部数据，不提供给模型 |
| `evidence_store/` | 逐步证据、事件与缓冲候选；没有逐步正式 claim 入账 |
| `stages.json` | 已封口阶段、开放阶段、已完成步数、未配对动作、实际收到的用户任务文本 |
| `stage_jobs/` | 不可变阶段快照及证据；没有对应结果时状态为 pending |
| `claim_batches/` | 一阶段一次提交，含多个 claim 节点及 evidence_ids，结果状态 ready |

job ID 固定，已完成作业重试不重复插入；已有输入哈希不一致会报错。阶段作业失败会向读取进程暴露异常，作业仍在磁盘上可重启重试。当前无自动退避/错误状态面板。批次记录实际完成时间；claim 中 `available_after_seq` 只是不得早于的事件下界，不代表当时已经完成后台生成。

claim 的真伪和使用状态保持分离；测试成功不会自动变成补丁正确，版本/环境未知时不生成支持边。`edges` 当前为空，依赖、反驳和语义支持仍待实现。

## 结束与恢复

- 收到 agent finish：正常封口最后阶段，触发末批 claim。
- 空闲超时、Ctrl+C、关闭 reader：暂停；不封口开放阶段，不 flush 未配对动作。相同目录可恢复。
- `--abort`：读取结束后显式永久中断，已完成步骤的尾阶段标为 incomplete 后入账；未完成动作列在 pending 中，不伪造结果。
- 事件先持久化，处理未完成时重启会重放；步骤存储和作业提交均幂等。只允许一个事件 reader，claim writer 是其专用单线程后台队列。
- 不承诺生产环境的并发读写、系统断电或长期大规模吞吐保证。原始日志有 thought/未来记录，只允许内部恢复，未来 API 必须使用证据白名单接口。

## 已完成验证

`python tests/test_online_ledger.py` 的 5 项测试通过：封口前没有正式 claim；阶段结束生成多节点；结束前边界只封旧阶段；配对动作跨重启保留；原生事件重复幂等/冲突拒绝；前缀不变；计划参数白名单；显式异常结束；实际 JSONL 分次追加和半行写入；后台任务提交。

`python -m segmenter.audit_online_ledger` 对固定开发集中的 SWE/Terminal 各一条真实日志按因果顺序输入，中途重启并重读前缀。产物 `eval/online_ledger_smoke_v1/report.json`：
