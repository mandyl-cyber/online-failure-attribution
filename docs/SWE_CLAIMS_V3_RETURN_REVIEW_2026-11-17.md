# v3 阶段摘要回传复核

日期：2026-11-17。结论：工程路径可运行，摘要语义尚不满足账本接线条件。保留原始结果，不修补失败 JSON、不扩大运行、不训练或宣称分段质量已经改善。

## 材料与完整性

回传目录为 `swe_claims_v3/`。六条请求、参考要点、protocol 与本地冻结材料一致；runner/core 代码指纹一致。实际发送的 prompt、模型别名、温度、输出预算、请求哈希均已核对。五条 ready 响应重新通过引用映射校验，与保存的 claims 一致。

六条均为 finish_reason=stop，无缺失/未决作业，无输入字节超限。失败请求是模型生成 JSON 内的 `"..." + "..."` 字符串拼接语法，不是输出 token 截断或网络错误。

模型标识仅有 qwen-local 别名：这不充分确定权重版本、量化方式和服务实际启动配置；后续能力诊断需补模型元数据，不能仅凭别名认定可重复模型环境。

## 主要问题

1. **把提示语当作已发生的事实。** Keras 和 Prettier 编辑回执中的 “Review the changes ...” 被写成“已经复核”。两条均缺乏已复核证据。
2. **把修改升级为正确性保证。** 看到 tf.cast 与 endpoint 分支后，生成“正确处理 endpoint、准确计算 step”，缺少实际验证结果。
3. **引用存在但不充分。** Yarn 版本只引裸数字输出，漏引命令；完成编辑/提交只引 action；“纠正错误后成功”只引最后输出，没有引用前后动作。
4. **低价值记录挤占摘要。** 多次任务列表数量更新被保留，关键 dtype 条件、axis 后端限定和具体成功示例被省略。去掉六条限制并没有自动解决内容选择。
5. **失败响应同时含严重误读。** verification_blocked 原始文本把 `absl present? False` 写成存在，且把 TensorFlow 导入失败写成 linspace 成功导入。即使修正 JSON 也不能解决这些语义问题。这些只计作失败响应定性发现，不混入17条合法 claims 的分母。

仍有有效输出：Tooltip 的 Partial<PopperProps> 类型修改、Git 提交及改动计数、Node 示例的失败概述基本得到支持。不能据此把全部摘要判为无用，也不能据五条格式合法宣布稳定。

## 下一步决策

当前停在 P3 语义关口，尚未进入 P5 在线账本。现有结构/映射和恢复测试仍有效，但它们不会检测上述语义错误。

下一项工作应是小批能力定位，而非继续扩大 prompt 或铺全量标签：

- 固定典型失败片段，区分“请求检查”与“检查完成”、“依赖缺失”与“依赖存在”、“代码改变”与“行为验证”；用短而完整的动作—观察证据检查错误是否仍发生。诊断窗口不是新的 gold stage，不用于边界指标。
- 分别评价断言忠实性、引用充分性和内容选择，不以一个笼统准确率掩盖问题；避免为提升覆盖而加入无依据内容。
- 先补远程权重/服务配置信息；若同一 Qwen 在短完整证据上仍稳定误读，再使用小批更强模型作独立能力对照，或准备经过复核的监督目标。未确定环境和目标质量前不启动 SFT/LoRA。
- 服务端约束解码可作为独立格式改进，但不能当作对上述语义问题的解决方案。继续保留 prompt_only 作为明确基线。

本轮未改变分段模型与 stage；这些发现不能归因于分段准确率低。也未用不同样本的 v2/v2.1 分数宣称 v3 改善或退化。
