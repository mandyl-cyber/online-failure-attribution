# 事件输入修复 v2：交付范围与验证

本轮优先修复输入层，不训练模型、不更换划分器、不发起新一轮摘要提示实验。入口为 `segmenter/adapters/openhands.py`。

## 已修复

1. `_s` 仅对明确的 text/input_text/output_text 文本块列表提取文本；其他结构化列表按 JSON 保留。以前任务字典没有 text 键，整条计划会退化为空白行。
2. task_tracking 保留完整公开参数，包括 command、task_list、status、notes。所有工具额外保留 `attrs.public_action_args`，避免可读 action 表达未涵盖的参数丢失。thought 与内部 handoff 字段不混入公开工具参数。
3. 有 cause 时按 ID 配对；没有 cause 且只有一个候选时采用明确标记的 fallback；多个候选时拒绝猜测并记录诊断。
4. 相同 ID、相同原始事件去重；相同 ID 内容冲突立即报错。去重作用域为当前 adapter 实例，跨重启需重新回放或持久化状态。
5. 动作按接收顺序输出。结果乱序到达时保留各自观察接收序号；步骤可用序号是实际输出时的 feed 序号，不能把它误作步骤号或原生日历时间。
6. 明确 flush 仍可输出不完整步骤，但标记 missing_observation_at_flush，不伪造成功结果。未匹配观察记录诊断，不错误附着到其他动作。
7. 已声明的 truncated 与明显文本截断标记进入 input_integrity.issues。未发现标记时 observation_complete 保持 unknown/null，不宣称完整。
8. follow 指定 --out 时，保存 input_diagnostics.json；Step JSON 中保留 input_integrity、原始事件哈希及公开参数。错误路径也保存已积累诊断。

## 验证结果

- 6 项测试覆盖结构化计划、非文本内容、乱序结果、可见序号、重复/冲突、歧义配对、缺失观察、截断和 chat 转换。
- 原有生命周期与 confirmation 测试通过。
- 对 12 条轨迹中曾丢失的 16 个公开计划调用重新读取原始日志，验证源哈希、精确调用 ID、完整参数和 notes 保留。报告：`eval/event_input_repair_v2/report.json`。这不是全量轨迹回放成绩。

## 不能据此宣称已解决的部分

- 无声明的上游截断无法仅凭文本可靠恢复。非文本内容保留结构，不代表能够读取图像语义。
- 多段观察、实时 stdout 增量等协议尚未定义：未输出前的多次观察明确拒绝；已输出后追加观察会进入 unmatched 诊断，不能算已合并。
- 观察早于动作到达时记录 unmatched，不自动回填；应由接入协议保证顺序或后续增加明确的重排层。
- 当前去重表与接收序号驻留内存，不是持久化恢复实现；输入哈希是溯源校验，不代替原始日志保存。
- follow 的 idle/中断仍会结束本次跟读并 flush，缺失观察已有标记，但尚未改造成持久化暂停/恢复。
- 下游必须读取完整性字段再决定是否接受 claim；本轮未修改尚在开发的账本语义逻辑，不宣称所有下游已经执行拒绝策略。
- 修复改变计划 action 文本及长度。旧模型可加载不等于新输入分布下性能不变；冻结旧数据与已有分数不覆盖，后续应另做输入 v2 对照。

## 后续顺序

先做一批真实事件流的转换回放审计（步数、配对、未匹配和标记分布），再把完整性门槛接到 claim 作业创建处。然后验证暂停恢复与部分观察协议。当前无需再次调用远程模型来验证参数丢失修复。
