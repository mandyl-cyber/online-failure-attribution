# 事实侧栏 stage 摘要：远程 Qwen32 回传审查

## 口径

同一批冻结的 9 个任务组、28 个 stage source snapshot；v3 与 v4 的共同可运行集为 8 组、24 次调用。v4 使用相同 Qwen2.5-32B-Instruct-AWQ、temperature 0、2048 输出 token，增加观察事实侧栏和写入前守卫。1 组因固定 8192-token 上下文限制整组排除。这里是开发兼容试验，不是独立任务泛化评估，也不是在线端到端测量。

| 指标（共同 24 次调用） | v3 | v4 |
| --- | ---: | ---: |
| 可写入 | 21 | 23 |
| 失败 | 3 | 1 |
| 可写入 claim 数 | 65 | 54 |
| 输入 token 总数 | 39,223 | 51,352 |
| 输出 token 总数 | 3,981 | 4,062 |
| 生成请求用时总和 | 74.256 秒 | 73.182 秒 |

v4 的输入 token 增加 12,129（约 30.9%）。请求用时相近只是本次小样本观察，不能推出在线排队和 stage 封口后的实际延迟。v4 的 54 条可写入 claim 中，有 **16 条与事实侧栏的通用 summary 逐字相同**；这说明模型明显依赖提示中的模板句，claim 数下降不能直接解释为压缩更好。

旧版 3 次失败分别是两次把非观察证据标为 tool observation，以及一次输出不是单个合法 JSON。新版只失败 1 次：Django 16631 的合并摘要把任务清单中的 `auth_tests` 写成“测试已成功运行”，却没有引用测试观察；守卫正确拒绝。该次失败仍保留原始响应，不能计为有效 claim。`conda run` 的非零返回正是脚本“存在失败请求则退出 1”的约定，不是模型服务崩溃；其余 23 次结果已经写盘。

## 按冻结检查点审查

- Django 12406：v4 合并摘要不再把 `sed` 查看测试源码写成“运行测试”；但只保留“验证在所见范围成功”，丢失了 406 个测试和 14 个跳过的具体数值。拆开摘要保留了数字。
- Django 15382：v4 合并摘要保留了 Ctrl+C 中断，修复了 v3 漏报；但丢失明确的退出码 130，后续源码搜索也被写成重复的通用“只读”句。
- Django 15563：v4 知道 pytest 不可用，未称测试通过；但合并摘要没有分别说明 `pytest -q` 命令不存在与 `python -m pytest` 缺模块这两次失败。
- Django 16631：守卫拒绝了没有观察证据的测试成功断言。拆开的提交摘要可写入，说明拒绝的是合并输出的语义断言，而非整个任务的输入不可用。
- Matplotlib 26342：v4 记录文件编辑和 `NotImplementedError`；但“两个类现在有该方法”的表述没有说清观察到的方法来自继承，仍需保留原始证据避免误读。
- xarray 7229：v4 把计划清单中的修复与观察到的单项 `test_where` 通过分开，优于 v3 拆开时把清单描述写成已验证事实。通过范围仍应限定在那一次命令。
- VS Code 160342：v4 保留 `npm run test-node` 因缺模块失败及后续仅查看源码的区别；与旧版相比，部分路径细节被概括。
- Prettier 6604：v4 保留后续搜索位置，但没有明确提炼出冻结检查点中的 Bug 变体缺括号，读者仍难理解该 stage 的问题。合并摘要再次出现笼统“只读”句。

上述是对这 8 组可见案例和预先冻结检查点的定性审查，不应外推为总体 claim 准确率。`missing_critical=0` 只表示内部关键词覆盖检查未报缺失；它不会发现数字、对象、因果或工作目的被泛化的情况。

## 结论和下一步

事实侧栏与守卫改善了中断／失败的保存和高风险断言的拦截，但 **v4 还不适合直接替换在线默认摘要**。最直接的瓶颈是结构化事实的通用句被当成最终 claim；具体的测试数量、命令差别、文件对象和异常上下文随之丢失。

下一轮应把事实侧栏改为精简的结构字段与原始证据指针，减少可直接照抄的 summary 句；要求每条 claim 写出具体对象、结果和证据范围，并在关键数字与退出码缺失时标记待复核。保持同一批输入作开发回归检查，然后用未参与调提示词的新任务组验证。守卫应只处理可明确判错的断言，不要把“未提炼出有用摘要”伪装成 schema 成功。在线链路还需单独测封口到生成、排队、失败重试和恢复。

可复算的机械统计与逐组对照在 `pilot/stage_claim_facts_v1_return/`；原始远程输出在 `stage_claim_facts_v1/`。统计脚本：`python -m scripts.audit_stage_claim_facts_return`。
