## 完成范围

## 对瓶颈的更具体判断

1. **动作关系没有充分表达。** VERIFY→READ 可能是换任务，也可能是为同一个失败测试查入口。仅工具变化和路径重叠不足以区分，错误内容和被读取对象之间的关系有价值。
2. **计划正文存在输入丢失，但修复它不等于解决监督。** 原 legacy action 的计划步骤常只剩换行；恢复后能读到活跃目标。然而案例 02/03/04 表明，相似的计划状态变化有时切、有时不切。已有计划恢复消融也没有稳定总体增益，不能再次宣称恢复就会提高准确率。
3. **任务模板、agent 声明和金标阶段是三个不同层次。** 抽取任务明确给出八阶段流程，agent 计划常照抄模板，却未必按序执行。不能用模板阶段号直接当标签，也不能把声明 done 变成验证通过事实。
4. **部分语义边界确有歧义。** git status 既可能准备交付，也可能只是检查修改范围。本轮不读取后续，不把模糊例强制变成某个目的类别。

这些是目的抽样中的诊断证据，不代表全数据集主因占比。现有 0.5478 D0 指标保持不变。

## 下一轮应如何做

停止继续堆静态工具/路径类别。将下一轮问题限定为：**当前动作是否延续此前尚未解决的具体目标**，直接服务边界预测，而不是重训七类通用目的。

先做可审计的离线输入试验：

1. 为候选步骤保存初始问题的相关实体、当前动作/观察、最近未解决错误、最近实际编辑对象及当时公开计划；区分声明与观察。严格从前缀构建，不读取未来、金标或最终结果。
2. 对同一批步骤保留“原四步结构”和“关系证据输入”两版，验证证据是否真的补充了案例 01 的同目标排障关系，以及案例 05 的不确定性；显式允许无法判断。
3. 若需 Qwen，只用于远程离线候选复核/教师数据，在线仍用轻量模型。教师不得通过金标位置或下一步知道答案，其意见不覆盖金标。
4. 只有离线证据显示值得训练，才在现有任务分组 train/dev 上训练直接边界辅助特征；测试折固定。D0 为主、D1 为补充，精确率不得退化，区间支持正收益后再考虑旁路候选。

这是一项后续计划，本轮未生成上述全量关系特征、未调用远程 Qwen、未训练下一版，不承诺会提升分数。
