# SFT 教师候选回传检查

148 个输入全部完成预检，54 个满足 8192 token 总预算，94 个超限。训练集 116 个中有 47 个入选、69 个排除，开发集 32 个中有 7 个入选、25 个排除。输入长度范围为 2878 至 53291 token。当前数据存在明显的短输入选择偏差。

实际生成 54 次，51 次通过既有校验、3 次失败。回传输入 SHA 与任务组字段均已逐条对齐。逐 claim 重检保留 142 个候选，拒绝 5 个，3 个请求有关键事实覆盖标记。所有候选的全面语义复核仍待完成。

失败原因包括以下三项。

- xarray 的一条 claim 使用 stage-observed-facts-v1 的事实 ID 作为证据引用，违反原始证据引用协议。
- MUI 的输出仅引用 action 就宣称实现正确、测试通过，来源与正文均有升级风险。
- Matplotlib 的 pickling 手写脚本确实运行两种用例，观察输出 Both pickled successfully 并以 0 退出。现有测试框架专用成功守卫误拒了该范围内的成功描述，应由证据复核修正。手写脚本的成功不能自动外推为整个测试套件通过。

当前仍需完成原始证据复核与修正答案，才能形成 SFT 目标。应优先核对来源和手写脚本案例，再处理长输入。长输入方案需要保留完整关键观察，可考虑按证据单元分块抽取后汇总，并在最终按 stage 评分时统计所有分块的遗漏和开销。

可复算检查为 python -m scripts.audit_claim_sft_teacher_return，产物位于 pilot/claim_sft_teacher_return_v1/audit.json。原始回传位于 claim_sft_teacher_v1。当前尚未导出训练目标或启动 LoRA。
