# SWE 连续目的标注：Qwen 预检与五步试跑

日期：2026-11-16。按照 `remote_pilots/swe_purpose_v1/README.md`，本轮只做 package 哈希核验、tokenizer 预检和训练集首五步试跑；**没有执行 935＋350 步完整标注，没有训练新模型，没有改变在线默认划分器**。

## 实际配置

- 本地已有 `Qwen/Qwen2.5-7B-Instruct` snapshot `a09a35458c702b33eeacc393d103063234e8bc28`。tokenizer 使用同一 snapshot；`config.json` 的 `max_position_embeddings=32768`，本机临时服务也以此为实际上下文上限。
- 临时服务的 `/v1/models` 返回 `qwen-local`；服务地址 `http://127.0.0.1:30001/v1`，BF16，RTX 5090。服务仅为试跑启动，完成后已停止。环境和精确命令见 `pilot/swe_purpose_qwen_v1/train/first5/ENVIRONMENT.txt`。
- 输入保留完整历史前缀，预检为输出预留 1,200 token，再留 128 token 余量。没有静默压缩或删除超限步骤。训练和开发包 `inspect` 均通过文件内容哈希，分别为 25 条/935 步、10 条/350 步。

## 首五步试跑

另用 `train/first5/` 保存 `--limit 5` 的结果，避免客户端把 5 请求的 `preflight.json` 覆盖完整训练预检。实际 5 步中 **2 个 valid、3 个 failed**；失败均在默认两次尝试后仍未通过：

| 请求 | 结果 | 可观察原因 |
| --- | --- | --- |
| `TRAIN_001_s00001` | 失败 | `step_id=1` 却引用 `field=task`；协议要求任务引用使用 `step_id=0`，且至少一处引文来自当前步骤 |
| `TRAIN_001_s00002` | 通过 | `ENABLE`，结构与逐字引用校验通过；不代表语义已人工核验 |
| `TRAIN_001_s00003` | 通过 | `ACQUIRE`，结构与逐字引用校验通过；不代表语义已人工核验 |
| `TRAIN_001_s00004` | 失败 | 引用很长的 observation 后 JSON 在引文中途结束；服务固定返回 `finish_reason=stop`，该字段不能证明输出完整 |
| `TRAIN_001_s00005` | 失败 | 目的输出为 `ACQUIRE|ENABLE`，不是七个单一合法标签之一 |

原始答复、错误、运行身份在 `pilot/swe_purpose_qwen_v1/train/first5/`。客户端 `audit.json` 对包中全部 935 请求计数，因此当前 `valid=2, missing=933` 包括**未尝试的 930 步和试跑失败的 3 步**；不能说已经对 935 步发起请求。两次尝试共发生 8 次本地模型调用。`run_manifest.json` 固定包、提示、模型 ID、tokenizer、上下文和服务配置。

## 结论及下一步

按远程说明中的停止条件，**不能继续原协议的完整 1,285 步标注**：上下文超限 36.7%，首五步严格通过率仅 2/5。问题既包括前缀太长，也包括证据 ID、枚举值和长引文导致的输出格式不稳定；不能只靠扩大重试次数把失败伪装成可用标签。

下一轮应先冻结一个**新版本**的因果前缀压缩方案，保留当前步原文及必要近期证据，明确所有删减/截断标记；以训练/开发全包重新做 tokenizer 预检。随后在**新输出目录**试跑不同轨迹和不同长度的短样本，固定短引文上限、只允许一个目的枚举值，并校验实际输出是否完整。通过门槛后才运行训练与开发完整初标，再做独立 AI 复核、轻量分类器训练和边界 F1 对照。旧结果目录保留原样，不混合不同协议。
