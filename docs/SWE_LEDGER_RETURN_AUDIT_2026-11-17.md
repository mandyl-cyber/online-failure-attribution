## 结论

48 个请求均保存了模型响应，三组有效作业全部为零。记录中没有连接失败；当前阻塞是输出协议与模型适配，不能据此比较分段好坏，更不能报告账本语义准确率或 failure attribution 准确率。

输入指纹已核验：本地 Windows JSONL 为 CRLF，远程为 LF；只转换记录行尾后的 SHA256 与远程 config 完全一致。没有修改 JSON 字符串内容或证据文本。原始输出未改动、没有接受或修复任何 claim。

| JSON 无法解析 | 1 | 1 | 0 | 2 |

另有三组各一个预检超预算作业未调用，仍保留在 manifest。35 个响应是完整 stop+JSON，其中 31 个通过字段 schema；引用校验仍失败。11 个未完整输出不尝试补括号或恢复半条 claim。

完整 JSON 中共 96 个 claim、118 条引用：

- 94 条引用文本在指定证据内有且只有一处逐字匹配，但模型 start/end 错误。
- 4 条文本有多个逐字匹配位置，不能唯一定位。
- 20 条文本不在指定证据中逐字出现，可能含转义、改写或其他问题，本轮未替它们做模糊匹配。
- 没有一条引用的原始 start/end 与原文同时正确。

这些是完整 JSON 子集中的引用统计，不是全体语义准确率。唯一逐字匹配也不证明引用支持 claim。

模型在 kind 中还输出了 tool_observation、agent_assertion、observation 等非法值，说明 kind 与 basis 概念混淆。样例包含长段源文件复制及把源代码行号当字符位置的情况。当前接口要求模型同时概括、分类、复制长引用和计算 Unicode 字符偏移，负担过重；此问题属于本轮实验设计需要修正的部分。

响应 usage 汇总：prompt 339398、completion 56032、total 395430 token。这是服务端报告值，不能等同计费或实际 GPU 成本。

## 修复决定与重跑范围

1. 保留 v1 原始输出和失败结果，不放宽原校验，不把离线改写后的输出混入 v1 分数。
2. 下一版在程序侧为原证据生成有精确字符范围的片段目录。模型仅返回 claim 和片段 ID；start/end/quote 由程序查表还原。非法/外来 ID 仍拒绝，不使用模糊匹配。
3. 缩短输出 schema，区分事实类型与证据来源，给出合法枚举示例；减少重复抄写原文。先保持输出上限并记录 length，不以静默截断减少超限。
4. 先做约六个请求的接口兼容性检查，覆盖三种分组及至少两个任务。此阶段只判格式、引用和耗时，不测划分优劣。新协议和运行器尚未在本轮实现，暂不执行重跑。
5. 兼容性通过后，三组全部按统一 v2 协议重新生成并运行，使用独立目录；不能仅重跑某组，或只保留成功响应。更换输出协议会改变实验条件，因此 v1/v2 结果不可直接混合。
6. 有合法输出后再审查语义遗漏、无证据断言与重复事实。依赖图及归因仍未进入评估，不能提前推断下游效果。
