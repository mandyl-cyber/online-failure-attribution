# 目的信息对在线边界划分的受控开发实验

日期：2026-11-14。目的：检验目的信息能否在相同可见信息和任务组划分下改善边界预测；不将结构通过率作为语义准确率。

## 冻结执行顺序

1. 核验 20 条、735 步包及已有监督数据。通过完整 action/observation 哈希和步号匹配金标；不按名称猜测。仅严格匹配子集进入主评分。
2. 独立 label-score-v1 特征探测：使用原目的定义，不训练 Qwen；完整当前前缀；不读金标、未来步骤或以前生成的标签。将 A–G 映射到七个目的，读取模型下一 token 的七选项相对概率。这个数值不视为校准置信度，也不等同原 JSON/引文协议通过。保留模型输入摘要、配置、原始分数、耗时和显存指标。
3. 保持原 32,768 上下文、1,200 输出预留及 128 模板余量用于可容纳判定，即使本探测只输出一个选项也不扩大样本。超限不截断、不生成，明确记 missing。模型单实例串行，单次尝试，按请求持久化，重启不重复；禁止静默换模型/提示/数据。先观察首五个样本，再按冻结配置完成。
4. 重建可用字段的结构特征，明确不是旧 461 条完整特征基线复现。用统一四步因果窗口比较 structure、purpose、fusion、structure+availability（缺失对照）及目的变化直接切分。缺失样本全部保留，不能只对模型成功步骤评分。
5. 在严格匹配任务组子集上沿用原 fold ID，外层测试折与内层开发折独立，剩余折训练。LR C=1，开发折选择阈值 0.10–0.80/0.05；不根据测试得分重改提示。报告 D0 ±1、最终 ±1、精确边界、误报和漏报、分来源、配对任务组 bootstrap 95% 区间。另报告 purpose/fusion 标签可用覆盖率。样本只包含部分来源时，不臆造跨来源结论。
6. 先运行协议/边界条件测试，再完成推理和评估。依据固定规则给出结论：fusion 相对 structure 的 D0 提升至少 1 个百分点且区间下限 >0，才称该小样本有正向证据；否则为未证实，负向则如实报告。无论结果如何，不替换在线默认模型。
7. 更新报告和交接，保存复现命令、局限与下一步。没有新增人工金标，不报告目的分类准确率，不启动大规模微调或外部 API。

## 已知限制与下一步门槛

- 主评分仅限内容哈希吻合的 Terminal-Bench 10 条；SWE 原始版本映射缺失，需取得原始映射/内容才能扩大严格评分。
- 数据属于已经研究过的开发集，不能称盲测。10 个任务组置信区间会很宽；收益仅说明继续扩样有价值。
- 目的描述工作类型，不直接表达子目标身份。七选项位置偏差、超长前缀缺失、字段丢失、原始任务中提示均可能影响结果。
- 推理依赖完整前缀，运行耗时不代表毫秒级在线部署；D0 是步骤信息可见时限，不是墙钟零延迟。若有信号，下一阶段才考虑蒸馏到小分类器及补子目标/对象特征。
