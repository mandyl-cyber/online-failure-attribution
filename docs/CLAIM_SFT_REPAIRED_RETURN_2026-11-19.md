# 原生计划恢复后的教师回传检查

本轮原始汇总为 148 个父 stage、404 次实际生成、391 次通过现有校验、13 次失败，产出 748 条可写入候选。请求耗时总和为 1536 秒，约 25.6 分钟。

逐证据检查确认子请求中的记录与恢复后的来源一致，缺失记录均能由已知源缺口或明确单步超限解释。5 个已知源缺口被预检排除。分块记录仍有 90 个单步超限。

父级 ID 需要规范化。恢复数据的 manifest 同时含旧输入父 ID，新分块又使用恢复后输入 ID。快速统计曾给出 83 个全部通过父 stage。统一映射后的正确结果为 86 个输入完整，其中 78 个全部子请求通过。后续以 pilot/claim_sft_repaired_return_v1/audit.json 为准。

原始 13 次失败包含 9 次 unqualified_success_assertion、3 次观察引用不足和 1 次测试动作识别问题。阅读原文后确认一部分是来源升级，一部分是规则误报。例如 Implement fix、Verify fix 等阶段标题被旧正则误认为修复成功。另有 task list notes 的明确归属表述未被认可。已收紧成功断言匹配并增加 notes/indicates 等归属表达，11 项回归测试通过。

原始运行指标保留。scripts/recheck_repaired_teacher.py 对原始输出执行当前逐条守卫校验，另存 guard_recheck.json。此检查只提供格式、来源和关键词线索，最终答案仍需结合原始证据复核。当前尚未导出 SFT 目标或启动训练。
