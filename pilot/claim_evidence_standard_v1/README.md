# Claim 证据标准与开发参考 v1（2026-11-23）

目标是明确“每句话的证据最多支持到哪里”，修正 v4 回传中已复核的问题，并准备针对性 SFT 的候选材料。没有训练，也没有修改线上生成协议、划分器或现有模型。

## 已准备的内容

- `cases.json`：8 条问题的原输出、修正参考、AI 依据、原始记录偏移与引文；另加 2 条先前未进入有效摘要的关键失败事实。共 10 个案例。
- `reference_candidates.jsonl`：11 个完整生成片段的候选响应，共 23 条 claim，其中 8 个修正输入、3 个未改动对照。相同输入的两处修正合并成一个目标，保留其中其他已接受的 claim；不会用完整阶段输入只训练一条孤立纠错句。
- `token_preflight.json`：真实 Qwen tokenizer 的输入与输出预算结果。11/11 可容纳，最长参考输出 215 token，使用 8192 总预算、512 输出预算。
- `protocol.json`：来源、数据哈希、覆盖范围与使用限制。

这里的“完整”指该模型输入片段的整个参考响应，不是每个 stage 应有事实的穷举金标。两条失败事实所在片段原来只有引用错误的输出，候选保留拒绝记录并提供有合法引用的失败摘要；没有把其他未经复核的子句补成事实。

## 证据标准

| 可见证据 | 可以表述 | 不能据此表述 |
| --- | --- | --- |
| 动作请求 | agent 请求查看、编辑或运行什么 | 动作已经完成、编辑已经生效 |
| 源码片段 | 该片段展示的声明、分支与表达式 | 没有修改过、运行正确、未显示的方法行为 |
| 工具回执 | 工具报告创建／编辑成功，以及展示的具体内容 | 修复有效、任务成功 |
| 进度与完成输出 | 下载到哪个进度；哪条输出明确报告安装完成 | 用下载进度证明安装成功，或反过来把历史失败写成当前仍失败 |
| 计划、commit message、agent 回顾 | agent 声明的状态、目的或自述结果 | 独立验证过的代码行为；工具显示了这些文字也不改变其声明属性 |
| 失败输出 | 当时的错误、失败范围及后续是否有同对象恢复证据 | 仅凭后来成功删掉前面的失败，或把不同对象的成功当作恢复 |
| 条件命令链 | 已显示的分支与结果，未执行分支保持未知 | 从 `A && B && C` 的部分输出断言 C 已执行或不存在 |

额外要求：对象、文件、方法、包名和版本必须与引用一致；引用只能来自封口前当前输入可见的原始 ID。分页时不能借用其他页的未显示内容。每个事实子句都要有证据；无法支持就缩小陈述或省略，不能为了凑摘要补齐结论。

## 本轮具体修正

1. rings.py 第二页：删除“as_expr 回执证明没有修改”的推断，只描述页内实际存在的 Add 表达式分支。
2. polyutils.py：以其中实际定义的函数为对象，删除与 as_expr 编辑回执的虚构关系。
3. commit message：标为 agent_assertion，描述提交信息声称的目的。
4. 计划完成状态：引用真正的 task-list action，标为 agent_assertion；保留“pytest 不可用、使用直接脚本”的声明范围。
5. `which` 条件链：只报告显示的 apt-get 路径，yum 可用性保持未知。
6. 安装包：精确写为设置 venv 和 pip/setuptools wheels，不写成安装 Python 解释器。
7. 下载进度：引用中途进度，明确该引用没有报告安装完成；保留同一输入内另一个确实完成安装的 claim。
8. 编辑请求：明确 agent 请求将 `<` 换为 `<=`，不把请求当回执。
9. 补充当时的 externally-managed-environment 失败。
10. 补充因 ensurepip 不可用而创建虚拟环境失败。

三份未改动对照分别保留 SWE 的有限复现／pytest 不可用、Terminal 的实际转换完成、live smoke 的异常／失败编辑，防止纠错目标只剩“保守地不说任何结果”。

## 使用与验收限制

这些是 AI 复核的开发参考，不是人工金标。输入来自三份反复使用的工程会话；其规范 benchmark task-group 身份尚未全部建立，不能因为 session 名不同就声称按任务独立。没有生成 `train.jsonl`／`dev.jsonl`，所有记录都显式标为 `training_eligible=false`、`usage=development_only`，现有训练脚本不能直接把本包当训练集使用。

已核验：与原 runtime prompt 相同、修正不引用隐藏页或封口后的证据、所有候选通过原生引用和窄事实约束、真实 tokenizer 预算通过；37 项相关回归测试通过。**这些检查不等于参考语义自动正确，也不是模型生成质量提升实验。** 未运行新的模型推理、SFT 或 RL。

下一步先扩充同类案例并核对其完整事实覆盖，建立规范任务来源和独立新任务的评估集，再决定是否把开发参考转换为训练材料。若做 SFT，应保留成功结果与失败／恢复的平衡、使用完整片段目标，并另测引用支持、关键失败覆盖、错误完成声明、结构有效率及生成成本。不能拿本包证明泛化提升，也不能把未接受输出简单当成 DPO 的负例就自动训练。

## 复算

```powershell
python -m scripts.prepare_claim_evidence_standard --check
```

默认读取本机 `neural_ledger_acceptance_v4/` 和 `claim_sft_7b_reviewed_v2/adapter` 中的 tokenizer；可用 `--returns` 和 `--tokenizer-path` 指定其他机器路径。构建命令去掉 `--check`；该脚本只生成候选和预检，不加载模型权重、不训练。检查会重建原输入、目标和哈希，与保存的数据逐项比较，原始回传与旧训练数据保持原样。
